# Доработка управления стикерами — источник для плана (2026-08-06)

Заметки Julia, дословно, сгруппированы в четыре пункта.

## 1. Дубликаты стикеров

Начали встречаться дубликаты стикеров: `AgAD6xIAAv3NMUs`, `AgAD_xEAAsJVUEo`, `AgADzioAAuSTIEs`.

Хорошо бы, чтобы бот мог сверять степень похожести стикеров и при высокой похожести просто делать
одно описание на все стикеры и дублировать.

## 2. Проверка стикера в DM от админа

Хочу иметь возможность от лица админа отправить боту стикер в DM (без какой-либо команды), и бот
проверяет этот стикер по базе:

- если стикер найден — бот выдаёт текущее описание;
- если не найден — предлагает проанализировать и добавить;
- если нажимаю кнопку «Проанализировать» — бот процессит стикер как обычно.

## 3. Оптимизация анализа анимаций

Нужно оптимизировать работу с анимациями. Например, для стикера `AgAD7DoAAppnmEg` бот не смог
распознать, что кот быстро мотает головой.

Для анимаций надо делать не только ключевые кадры, но ещё и анализировать степень движения —
например, отличать всякие трясущиеся стики или стики с резким движением. Возможно, через отрисовку
шлейфа или что-то ещё.

Если для этого нужны дополнительные библиотеки — делаем этот анализ **опциональным** и включаем
только если всё настроено. Текущий маршрут анализа сохраняем.

## 4. Степень «нормисности» / «приемлемости» стикера

Есть много стиков с эротикой и непотребствами; хорошо бы, чтобы бот по дефолту такое не использовал
в новых чатах.

Сделать настройку минимального «уровня толерантности» стикеров:

- для нового чата по умолчанию `0.5` — бот следует среднему уровню приемлемости и не скидывает
  стики типа «го ебаться»;
- для чатов типа срачейки должны использоваться все, даже самые всратые стикеры — там «все свои»,
  и неприличные стикеры наоборот создают атмосферу анархии.
