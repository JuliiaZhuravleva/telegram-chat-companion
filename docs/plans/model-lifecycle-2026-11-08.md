# Протокол смены моделей ИИ

_2026-11-08. Повод: OpenAI отключил `o4-mini` (404 «deprecated»), и слияние описаний стикеров
молча перестало работать. Модель была зашита в коде, поэтому её замена потребовала релиза
(PR #88). Очевидная замена `gpt-5-mini` упала бы так же: она отвергает `temperature=0.4`._

## Решения владельца (2026-11-08)

| Вопрос | Решение |
|---|---|
| Кто переключает | **Только владелец.** Не все `admin_ids` (их больше одного) |
| Напоминание о новых моделях | **Через 90 дней** после последней смены модели роли |
| Как часто сверять | **Раз в неделю, молча**, если ничего не изменилось. Главный сигнал — ошибка при вызове, предупреждение заранее — дата отключения в каталоге (2026-11-09) |
| Дорогие модели (`EXPENSIVE_MODELS`) | **Только через сессию разработки.** Бот их **не предлагает**: ни в кандидатах, ни в напоминаниях |
| Модель сняли | **Автопереключение**, если кандидат дешёвого уровня, прошёл пробу и стоит **не больше +10% за вызов**. **Уведомление владельцу — всегда** |

Как читается «+10%»: по цене **вызова** (токены, измеренные пробой, × прайс), а не по цене
токена. `gpt-5-mini` дешевле `gpt-5.4-mini` за токен, но на слиянии тратит 216 выходных токенов
против 19–38. Более дешёвый кандидат разрешён. Роль, стоящая на одобренной дорогой модели (сейчас
слияние стикеров на `gpt-5.4-mini`), при снятии сама **не** переключается: уведомление, запасной
путь, дальше сессия.

## Что есть сейчас (на `6dc6c81`)

Это самый вероятный следующий алерт.

## Протокол

### 1. Роли вместо имён

Каждый вызов модели принадлежит **роли**: `reply`, `reply_fallback`, `vision`, `transcription`,
`relevancy_judge`, `sticker_merge`, `advice_reader`, `embeddings`. Код спрашивает модель роли и
не называет её сам. Значение собирается так: YAML → `bot_config` (`model.<role>`, глобально, по
чатам не переопределяется) — то же «NULL = не переопределено», что и в трёхслойной схеме.

`embeddings` в админке **только показывается**: смена модели меняет векторное пространство под
строками, которые никто не пересчитывает (CLAUDE.md, «task_type»). Смена — только миграцией с
переиндексацией.

### 2. Каталог моделей — `config/models.yml`

Одна запись на модель: провайдер, семейство (`gpt-5-mini`, `gemini-flash`), уровень
(`cheap` / `expensive`, сверяется с `EXPENSIVE_MODELS`), цена с датой проверки, какие роли
способна закрыть, известные ограничения (`temperature_fixed: 1`, `reasoning: true`,
`json_mode`), **дата отключения**, если провайдер её объявил (`shutdown: 2026-…`). У Cloudflare цена — нейроны из общего бесплатного пула 10 000 в день (один на все проекты), и правило «+10%» считается в них. Пишет его сессия разработки, не бот: цены в API провайдеров не отдаются
(ПРЕДПОЛОЖЕНИЕ, проверить по OpenAI и Gemini при реализации). Модель, которую провайдер
показывает, а каталог не знает, бот называет «новая, нужна проверка» — **без кнопки**.

### 3. Проба перед любой сменой

Один настоящий вызов с параметрами роли: её температура, JSON, картинка для `vision`, короткий
аудиофрагмент для `transcription`, типичный промпт. Проба проходит, если ответ непустой, JSON
разбирается, `finish_reason` не `length`. Она меряет токены, и цена вызова для правила «+10%»
берётся отсюда. Без пройденной пробы ничего не записывается — ни вручную, ни автоматически.

### 4. Журнал смен — таблица `model_changes`

Кто (владелец / `auto`), когда, роль, было → стало, результат пробы, цена вызова до и после,
причина (`manual` / `retired` / `freshness`). Из журнала берутся «с какой даты стоит модель» для
90 дней и кнопка «Вернуть».

### 5. Проверки

Они расставлены по ценности, а не по частоте. Модели меняются редко, поэтому опрашивать
провайдеров каждый день незачем. Решает то, что срабатывает в момент поломки, и то, что
предупреждает заранее.

**Во время работы — главный сигнал** — 404 с «deprecated» / «not found» на имени модели становится отдельным
`ModelRetiredError`: не повторяется, не считается «перебоями», сразу запускает пункт 6. Сегодня
такой вызов был подписан в алерте как «ответы» — для владельца это ложная тревога не о том.

**Заранее — по дате отключения.** OpenAI и Google объявляют отключение за месяцы. Сессия
записывает дату в каталог, и за **30 дней** до неё бот пишет владельцу: «X отключат <дата>,
вот проверенные замены». Тот же пункт 6, только с запасом времени и без автопереключения:
пока модель жива, решает владелец. Это единственный механизм с предупреждением заранее;
сверка списков его не даёт. Модель, вероятно, пропадает из списка в день отключения
(ПРЕДПОЛОЖЕНИЕ).

**Раз в неделю, бесплатно и молча** — одна задача, у которой три дела:
- сверить списки моделей у провайдеров (OpenAI `/v1/models`, Gemini `models.list`). Модели роли
  нет в списке → «снята», пункт 6. Нужна для редких ролей: слияние стикеров вызывается, только
  когда админ правит стикер, и мёртвая модель могла бы ждать первого вызова несколько дней;
- проверить даты отключения из каталога (окно 30 дней);
- проверить правило 90 дней (ниже).

Если ничего не изменилось, задача ничего не пишет.

**Раз в 90 дней на роль** (проверяется той же еженедельной задачей) — если в каталоге есть модель новее того же семейства **и дешёвого
уровня**: «Ответы работают на X с <даты>. Вышли Y, Z. Сравнить?». «Сравнить» запускает оценку на
20–50 реальных случаях роли (правило проекта); до запуска показывается цена в долларах и в доле
общих лимитов. Итог — рядом, с ценой за вызов; кнопки «Переключить», «Оставить», «Напомнить через
30 дней». Дорогие модели в напоминание не попадают.

### 6. Модель сняли

1. Кандидаты: каталог → роль → тот же провайдер или запасной → только `cheap`.
2. Проба по каждому, по цене вызова.
3. Есть кандидат с ценой ≤ 1.10 × текущей → записать, `model_changes.reason = retired`,
   **уведомить владельца**: что сняли, на что переключено, цена было/стало, кнопка «Вернуть»
   (возвращает на запасной путь, а не на мёртвую модель) и «Выбрать другую».
4. Нет такого кандидата или роль на одобренной дорогой модели → не переключать, роль работает на
   запасном пути, если он есть, **уведомить владельца** со списком прошедших пробу и их ценой.
   Дорогие в списке не показываются, вместо них строка «дорогие варианты — через сессию».

### 7. Экран «Модели» в админке

В глобальных настройках, виден и нажимается **только владельцу**. Строка на роль: модель, цена
вызова за 30 дней (`response_log`), с какой даты, статус ✅ / ⚠️ превью / ⛔ снята. Тап → кандидаты
из каталога (только `cheap`) с ценой → проба → подтверждение. Остальные админы экран не видят:
у бота сейчас два глобальных админа.

Владелец — новая настройка `owner_id` (env или `bot_config`), не первый элемент `admin_ids`.
Реальный id в репозиторий не попадает (CLAUDE.md, «This repo is public»).
