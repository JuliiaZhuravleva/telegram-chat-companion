## Как читать этот чек-лист

Каждый пункт — «сделай → ожидается». Просто выполняй по порядку, ничего не нужно придумывать: все
названия чатов, тексты кнопок и ссылки ниже — готовые, скопируй-вставь. Отмечай `[x]` по ходу и
дописывай факт в скобках, если результат отличается от ожидаемого — это не обязательно баг (см.
пометки «если результат другой»), но должно быть зафиксировано.

## Раздел A — Оценка откровенности стикера в карточке + ручная правка (A-1, A-4)

> Что уже проверено юнитами (не повторять здесь): текст всех 3 состояний строки
> (`format_explicitness_line`), верное отображение бейджа «(вручную)» ровно в нужных местах,
> валидация ввода (reject-not-clamp), поведение кнопок при отсутствии прав/некорректном
> `callback_data`, проброс `is_manual` во все точки сборки карточки. Здесь — только то, что
> реально требует живого Vision-вызова и живой последовательности нажатий.

- [ ] **Шаг 0 (готовит реальные данные для всего раздела).** Отправить боту в личку **любой**
      стикер, которого точно нет в его каталоге (свежий паблик-пак). Ожидается: реплай «Такого
      стикера ещё нет в базе.» + кнопка «🔍 Проанализировать». Нажать кнопку. Дождаться финального
      текста карточки (не «⏳ Анализирую…»). **Записать `file_unique_id`** — он в первой строке
      карточки, `🆔 <code>...</code>` (в Telegram по нему тапом можно скопировать).
- [ ] Карточка после анализа содержит строку **«Оценка откровенности: N.NN · уровень приличия чата
      N.NN · ✅ пройдёт»** или **«... · ❌ не пройдёт»** (реальное число, не «не оценён» — если
      Vision вернул валидную оценку, что бывает почти всегда). Под текстом — ряд из 5 кнопок с
      числами `0.00 0.25 0.50 0.75 1.00`, кнопка «✏️ Указать число», НЕТ кнопки «↩️ Сбросить к
      авто» (оценка ещё не ручная — сбрасывать нечего).
- [ ] Нажать любую кнопку-пресет, например **`0.75`**. Ожидается: всплывающее уведомление
      `Оценка: 0.75 (вручную)`, карточка перерисовывается, строка оценки теперь заканчивается на
      **`(вручную)`**, и под текстом появилась кнопка **«↩️ Сбросить к авто»**.
- [ ] Нажать «✏️ Указать число». Ожидается сообщение-приглашение: **«Введите оценку откровенности
      стикера (0.0–1.0):»** + кнопка «✖ Отмена».
  - [ ] Ответить мусором, например `полтора`. Ожидается: **«Нужно число от 0.0 до 1.0. Попробуйте
        ещё раз.»**, диалог остаётся открытым (не сбрасывается).
  - [ ] Ответить числом вне диапазона, например `1.5`. Ожидается тот же текст ошибки (не «обрезано
        до 1.0» — reject, а не clamp).
  - [ ] Ответить валидным числом с запятой, например `0,10`. Ожидается: **«Оценка откровенности
        установлена вручную: 0.10»**, следом — свежая карточка с `0.10 · ... (вручную)`.
- [ ] Нажать «↩️ Сбросить к авто». Ожидается всплывающее уведомление **«Сброшено к автоматической
      оценке (не оценён до следующего анализа)»**, карточка перерисовывается, строка оценки —
      **«Оценка откровенности: не оценён (бот не отправит)»**, кнопки-пресеты на месте, кнопки
      «Сбросить» больше нет.
- [ ] Нажать «🔄 Запустить заново» на этом же стикере (реальный повторный Vision-анализ). После
      завершения — карточка снова показывает числовую оценку (не обязательно ту же — Vision мог
      ответить иначе). Это подтверждает, что реальный повторный анализ доходит до конца и не
      конфликтует с уже написанным (сброшенным) ручным состоянием.
- [ ] Применить `sticker_knowledge`-фикстуру из `.q2-fixtures.sql` (замена `explicitness_score` на
      `NULL` по записанному `file_unique_id`). Открыть карточку заново — проще всего повторно
      отправить тот же стикер боту (сработает found-путь), либо через «🎨 Стикерпаки» в `/admin` →
      найти пак этого стикера → тапнуть по нему в списке. Ожидается строка **«Оценка
      откровенности: не оценён (бот не отправит)»** — состояние «проанализирован, но без числовой
      оценки», третье из трёх описанных владельцем в источнике плана.
- [ ] **Admin-only boundary.** С НЕ-админского аккаунта повторить один из тапов выше (пресет/сброс)
      на карточке, полученной от админа (переслать/повторно открыть недоступно — вместо этого
      просто отправить тот же стикер боту с не-админского аккаунта). Ожидается: бот НЕ отвечает
      карточкой found-пути от имени DM-check-хендлера (это же поведение уже покрыто прежним
      чек-листом B-2 из `sticker-management-2026-08-06` — здесь не повторяется подробно, если
      результат отличается — самостоятельный баг, не относящийся к Q-2).

## Раздел B — Сгруппированная панель настроек чата (B-1/B-2)

> Что уже проверено юнитами: состав кнопок каждого экрана, refuse на KB/Reactions через общий
> toggle-хендлер, re-render на «свой» групп-экран после переключения поля/сохранения tolerance,
> HTML-рендер, доступ не-админу/не-личке. Здесь — реальная навигация по экранам.
>
> **Известное ограничение (не баг, зафиксировано в ADR-0010 Decision 3 / item B-3, статус
> `pending`):** кнопки 4 групп на корневом экране пока БЕЗ статуса-подсказки (просто «💬 Поведение»
> и т.д., без «3/5 настроено» и подобного) — это работа B-3, ещё не сделана. Не отмечать как баг.

- [ ] `/admin` → «⚙️ Настройки чата» → пикер. Открыть **`QA Smoke — Alpha`** (см. раздел C ниже —
      если чатов много, ищи по этому названию, порядок в списке проверяется отдельно).
- [ ] Корневой экран панели: заголовок **«⚙️ Настройки чата»**, 7 строк кнопок — 4 группы (**💬
      Поведение**, **🧩 Модули**, **🎨 Стикеры**, **📏 Правила**), затем строка **📚 База знаний**
      и строка **😀 Реакции** (обе с статусом ✅/⚫, возможно с маркером «унаследовано» — это старые
      строки, не трогали в B-2), и «◀️ Назад» (ведёт в главное меню `/admin`, не в пикер — так и
      задумано, не регрессия).
- [ ] Открыть **«💬 Поведение»**. Ожидается заголовок-хлебная крошка **«⚙️ Настройки чата › 💬
      Поведение»** и только поля этой группы (не полный список всех 25 полей). Нажать «◀️ Назад» —
      возвращает на корневой экран (не в пикер).
- [ ] Открыть **«🧩 Модули»** (самая крупная группа — 8 полей). Переключить любое булево поле
      (тап по строке). Ожидается: экран перерисовывается **на том же групп-экране «Модули»**
      (не на корне и не в пикере) с обновлённым значением. Открыть корневой экран — статус KB/
      Reactions строк не сбился, если переключённое поле их не касалось.
- [ ] Открыть **«🎨 Стикеры»**. Найти поле `tolerance_level` (уровень приличия чата) и открыть его
      FSM-редактирование (та же механика, что в старой плоской панели). Ввести валидное число,
      например `0.6`. Ожидается сохранение и re-render **экрана «Стикеры»** (не корня).
      Отменить (кнопка отмены) на повторном заходе — тоже должно вернуть на «Стикеры».
- [ ] Открыть **«📏 Правила»** — экран открывается, хлебная крошка **«... › 📏 Правила»**, поля
      этой группы показаны корректно (это самая маленькая группа — удобно быстро свериться, что
      ничего не потерялось).
- [ ] Хотя бы на одном экране группы убедиться, что **маркер «унаследовано из глобального
      дефолта»** виден хотя бы у одного поля — у фиктивного чата `Alpha` он гарантированно есть
      (фикстура не задаёт `tolerance_level`/поля Правил/Реакций явно, см. заголовок SQL-файла).
      Если маркера нигде нет ни на одном поле ни одной группы — это баг, зафиксировать.
- [ ] Ограничения Telegram: пролистать по всем 4 группам подряд, ничего не падает с ошибкой
      «message is not modified» или обрезанным текстом/кнопками (мы намеренно взяли самую большую
      группу — «Модули», 8 полей — как стресс-случай на длину сообщения/число кнопок).

## Раздел C — Сортировка пикера чатов по активности (C-1)

> Что уже проверено юнитом (мокнутый pool): сам SQL-агрегат, отсутствие N+1, форматирование
> счётчика в подписи. Здесь — реальный визуальный порядок в живом пикере.

- [ ] `/admin` → «⚙️ Настройки чата» — открылся пикер с заголовком **«⚙️ Выберите чат для
      настройки:»**. Найти три фиктивных чата (если реальных чатов в whitelist много — пролистать
      кнопками ◀️/▶️, названия начинаются с **«QA Smoke — »**).
- [ ] Относительный порядок этих трёх строк: **`QA Smoke — Alpha · 50`**, затем **`QA Smoke —
      Alphaville · 5`**, затем **`QA Smoke — Bravo · 0`** — именно в этом порядке (по убыванию
      счётчика; реальные чаты могут перемежаться между ними или быть выше/ниже, это не важно —
      важен порядок именно между этими тремя). Число после «·» — счётчик сообщений за 24ч, не id
      (не должно быть автолинком/подсвечено Telegram как ссылка на юзера).
- [ ] Пагинация (`_PER_PAGE = 10`) продолжает работать: кнопки ◀️/▶️ листают дальше в том же
      убывающем порядке, номер страницы `N/M` корректен.

## Раздел D — Шорткат `/panel` (D-1)

> Что уже проверено юнитами: парсер ссылок (round-trip), одно/много/ноль совпадений по названию,
> отказ вне личных сообщений. Здесь — реальные команды, реальный текст ответов.

- [ ] `/panel` без аргумента. Ожидается: **«Укажи ссылку на чат (t.me/…, t.me/c/…) или часть его
      названия:\n`/panel название или ссылка`»**.
- [ ] `/panel t.me/c/9999000001` (готовая ссылка на фиктивный чат Alpha, см. `.q2-fixtures.sql`). <!-- check-plan-artifacts: allow telegram-id -->
      Ожидается: сразу открывается панель **этого** чата (корневой экран, как в разделе B) — минуя
      пикер, без промежуточных сообщений.
- [ ] `/panel -1009999000003` (сырой id чата Bravo). Ожидается: та же прямая открывалка панели <!-- check-plan-artifacts: allow telegram-id -->
      Bravo.
- [ ] `/panel Bravo` (однозначное название). Ожидается: панель открывается напрямую (одно
      совпадение — без списка кандидатов).
- [ ] `/panel Alpha` (совпадает и с «Alpha», и с «Alphaville»). Ожидается: **«Нашлось несколько
      подходящих чатов, выбери нужный:»** + 2 кнопки с полными названиями. Тап по одной из них
      открывает её панель.
- [ ] `/panel QA Smoke` (совпадает со всеми тремя). Ожидается тот же список кандидатов, уже из 3
      строк.
- [ ] `/panel zzz-such-chat-does-not-exist`. Ожидается: **«Не нашёл такого чата в whitelist.»**
- [ ] **Admin-only + личка-only.** С НЕ-админского аккаунта: `/panel Alpha` — бот не отвечает
      вообще (команда скрыта/недоступна). Из группового чата (не личка) от имени админа: `/panel
      Alpha` — тоже без ответа (хендлер сам отсекает не-`private`).
- [ ] *(Опционально, если под рукой есть один настоящий чат из whitelist с публичным username)*:
      `/panel @username_чата` или `/panel t.me/username_чата` — резолвится через один живой
      `bot.get_chat()`. Если такого чата нет под рукой — пропустить: ветка уже покрыта юнитами
      (`test_admin_chat_panel_handler.py`, username resolve success/failure), фиктивные данные её
      не покрывают в принципе (см. заголовок SQL-фикстур).

## Готово, когда

- Раздел A подтверждает вживую все состояния карточки (авто-оценка, пресет, свободный ввод с
  валидацией, сброс, «не оценён после анализа», «(вручную)»-бейдж) и что реальный повторный анализ
  не падает.
- Раздел B подтверждает, что навигация по 4 группам работает, хлебные крошки корректны, возврат
  предсказуем (на свой экран, не на корень/пикер), маркер «унаследовано» виден хотя бы раз.
- Раздел C подтверждает порядок пикера по убыванию активности между тремя фиктивными чатами и
  корректность счётчика в подписи.
- Раздел D подтверждает все ветки `/panel` (ссылка, сырой id, одно/много/ноль совпадений по
  названию, admin+private-only) реальными командами.
- «Гигиена» выполнена: фикстуры убраны, утечки реальных id не найдено, автотесты зелёные.
